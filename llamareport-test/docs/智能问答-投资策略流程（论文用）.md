# 智能问答界面「投资策略」流程说明（论文用）

本文档描述智能问答界面中「投资策略」模块的完整技术流程，每个方法均给出实现位置与算法要点，便于论文中的方法章节撰写。

---

## 一、整体流程概览

```
用户触发
  ├─ 方式A：输入框提问（如“生成投资策略”）→ POST /agent/query → ReportAgent 解析后调用工具
  └─ 方式B：点击「投资策略」按钮 → POST /agent/generate-section (section_name=profit_forecast)
        ↓
get_report_agent().generate_section("profit_forecast", company_name, year, model_type)
        ↓
generate_profit_forecast_and_valuation(company_name, year, query_engine, model_type)
        ↓
  [1] 数据检索（RAG 三路查询）
  [2] 指标自动识别与输入变量表构建（LLM 结构化抽取，model_type≠clustering 时执行）
  [3] 数据验证与清洗（_validate_and_clean_data）
  [4] 相关性分析（_llm_correlation_analysis）+ 策略结论洞察（LLM）
  [5] 因子分析（_llm_factor_analysis）
  [6] 聚类分析（K-Means，LLM 生成 clustering_model）
  [7] 综合投资策略洞察（仅 model_type=all 时，LLM 整合四部分）
        ↓
返回 result_dict（含 indicator_extraction, variable_table, correlation_results,
     strategy_conclusion, factor_analysis, clustering_model, comprehensive_insight 等）
        ↓
ReportAgent 组装章节摘要（优先 comprehensive_insight，否则 strategy_conclusion + 因子/聚类摘要）
        ↓
前端展示：章节内容 + 可选结构化数据（表格/图表）
```

**代码入口**  
- Agent 查询：`backend/api/agent.py` — `POST /agent/query`、`POST /agent/generate-section`  
- 投资策略核心实现：`backend/agents/report_tools.py` — `generate_profit_forecast_and_valuation`  
- 章节封装：`backend/agents/report_agent.py` — `generate_section(section_name="profit_forecast", ...)`  

**模型类型（model_type）**  
- `all`：执行指标抽取 + 相关性 + 因子 + 聚类 + 综合洞察  
- `correlation_only`：仅指标抽取 + 相关性分析 + 策略结论  
- `factor_only`：仅指标抽取 + 因子分析  
- `clustering`：仅聚类分析（跳过指标抽取与相关性/因子）

## 二、各步骤方法详述

### 2.1 数据检索（RAG 三路查询）

**作用**：从年报中为投资策略提供「表格 + 文本 + 近三年核心指标」三类语料。

**实现位置**：`report_tools.py` 中 `generate_profit_forecast_and_valuation` 开头（约 1914–1935 行）。

**方法说明**：

1. **表格查询（table_query）**  
   - 查询内容：公司名 + 年份 + 关键指标/表格/主要指标，以及股息率、分红率、市净率、PB、ROE、净息差、NIM、非息收入、不良贷款率、核心一级资本充足率、拨备覆盖率、零售贷款增速、对公新兴行业贷款增速、房地产敞口不良率、风险加权资产等关键词。  
   - 目的：抽取结构化表格数据，供指标识别与变量表构建。

2. **年报文本查询（report_query）**  
   - 查询内容：公司名 + 年份 + 年报、管理层讨论与分析、财务指标、经营分析，以及上述财务指标关键词。  
   - 目的：补充管理层讨论与经营分析中的定性、定量描述。

3. **相关性专用查询（correlation_query）**  
   - 查询内容：公司名 + 年报、近三年、历年，以及净息差、ROE、ROA、不良率、拨备覆盖率、成本收入比、信贷成本、资本充足率、主要指标、表、财务数据。  
   - 目的：为后续 Pearson 相关性分析提供至少近三年的核心财务指标时间序列。

三路查询均通过同一 `query_engine.query(...)` 执行，结果拼接为 `forecast_data` 字符串，供后续 LLM 使用。

---

### 2.2 指标自动识别与输入变量表构建

**作用**：从年报多维度抽取指标并整理为「输入变量表」，满足相关性、因子、聚类对结构化数据的要求。

**实现位置**：`report_tools.py` 中 `generate_profit_forecast_and_valuation` 内，当 `model_type != "clustering"` 时执行（约 1968–2206 行）。使用 Pydantic 模型 `ProfitForecastAndValuation`（定义见 `models/report_models.py`）。

**方法说明**：

1. **多维度指标抽取（LLM 结构化输出）**  
   Prompt 要求从年报中按以下维度抽取（同一指标多期则多行，至少三年用于相关性）：  
   - **维度1**：核心财务指标（净息差、ROE、ROA、不良率、拨备覆盖率、成本收入比、信贷成本、资本充足率等；至少三年）。  
   - **维度2**：贷款产品维度（产品名称、余额、占比、不良率、余额变动率、增速等）。  
   - **维度3**：地区经营维度（地区名称、贷款/存款余额、存贷比、不良率、占比等）。  
   - **维度4**：行业贷款分布（行业名称、贷款余额、占比、不良率）。  
   - **维度5**：业务板块数据（板块名称、营业收入、净利润、资产规模、减值损失等）。  
   - **维度6**：资产负债结构（科目、日均余额、利息收入/支出、收益率/成本率、变动率）。  
   - **维度7**：时间序列数据（至少近三年年度指标，命名与单位一致）。  

2. **数据要求**  
   - 优先从表格提取；缺失标为 null；保留原始精度；标注数据来源（如页码）。  

3. **输入变量表（variable_table）**  
   - 每条记录包含：`variable_type`（收益类/盈利类/风险类/业务类/估值类/风险敞口类/其他）、`metric`、`value`、`period`、`unit`。  
   - 对 8 项核心指标（净息差、ROE、ROA、不良率、拨备覆盖率、成本收入比、信贷成本、资本充足率）强制要求：同一 metric 至少三年（多行，每行一个 period 与 value），以支持后续 Pearson 相关性与因子分析。  

4. **输出约束**  
   - 本步只输出 `indicator_extraction`、`variable_table` 及占位的 `data_sufficiency`；`correlation_results` 为空数组，`strategy_conclusion`、`clustering_model`、`factor_analysis` 为空或 null，由后续步骤填充。  

5. **实现细节**  
   - 优先使用 `llm.as_structured_llm(ProfitForecastAndValuation)` 得到结构化对象；若失败则用普通 `llm.achat` 再正则提取 JSON 并解析为 `ProfitForecastAndValuation`。  

---

### 2.3 数据验证与清洗

**作用**：保证中间结果符合 `ProfitForecastAndValuation` 模型，并修正 `data_sufficiency` 等字段类型。

**实现位置**：`report_tools.py` 中 `_validate_and_clean_data`（约 127–160 行），在指标抽取后、各分析步骤前调用（约 2249 行）。

**方法说明**：  
- 使用 Pydantic 的 `model_class(**data)` 做校验；若失败则做保守清理（去掉 `error`、空字符串等），返回可用的字典，避免后续步骤因类型或缺失字段报错。  

---

### 2.4 相关性分析

**作用**：基于输入变量表构建时间序列，计算核心财务指标两两的 Pearson 相关系数，并生成「高/低相关性结论 + 趋势 + 关键信号」的策略结论。

**实现位置**：  
- 相关性计算与 JSON 输出：`report_tools.py` 中 `_llm_correlation_analysis`（约 1663–1737 行）。  
- 策略结论洞察：同文件内，在得到 `correlation_results` 后由另一段 LLM prompt 生成 `strategy_conclusion`（约 2312–2354 行）。  
- 触发条件：`model_type in {"correlation", "all", "correlation_only"}`。

**方法说明**：

1. **_llm_correlation_analysis（Pearson 相关系数矩阵）**  
   - **输入**：`indicator_extraction`、`variable_table`、`year`、`llm`。  
   - **步骤 1**：从 `variable_table` 按 `metric` 分组，构建每项指标的 `(period, value)` 时间序列；指标名称与单位做标准化（如 ROE 与净资产收益率视为同一指标）。  
   - **步骤 2**：对 8 项核心指标（净息差、ROE、ROA、不良率、拨备覆盖率、成本收入比、信贷成本、资本充足率）两两判断：若存在**至少 3 个共同 period**，则计算该两列数值的 **Pearson 相关系数**，并输出一条记录，包含：  
     - `target_metric`、`driver_metric`  
     - `correlation`（r 值）  
     - `significance`：|r|>0.7 强相关，0.5–0.7 中强相关，0.3–0.5 弱相关，<0.3 无显著相关，并区分正/负。  
     - `interpretation`（简要业务解读）、`data_points`（共同时间点数）。  
   - **步骤 3**：数据充分性。若至少有一对指标有 ≥3 个共同时间点并已输出，则 `is_sufficient=true`，`sample_description` 写明时间范围（如「2022–2024年3期」）；否则 `correlation_results` 可为空，`is_sufficient=false`，`reason` 说明「共同时间点不足三年」。  
   - **输出**：仅一个 JSON 对象，包含 `correlation_results` 与 `data_sufficiency`；由 LLM 在内部完成时间序列构建与 Pearson 计算并按要求格式输出。  

2. **策略结论洞察（strategy_conclusion）**  
   - 在得到 `correlation_results` 和 `data_sufficiency` 后，若当前 `strategy_conclusion` 仍为空，则再调用一次 LLM。  
   - Prompt 要求基于 Pearson 结果（或当结果为空时基于 variable_table 与行业常识）生成四类内容：  
     - **short_term**：高相关性指标对及业务含义；  
     - **long_term**：趋势分析与长期投资启示；  
     - **risk_control**：低相关性指标与风险提示；  
     - **key_signals**：2–4 条洞察句（示例句式已在 prompt 中给出）。  
   - 输出为 JSON，包含 `strategy_conclusion` 与可选 `notes`，解析后写回 `result_dict`。

### 2.5 因子分析

**作用**：在指标矩阵上做因子分析（相关系数矩阵 → 特征值 → 因子数 → 载荷 → 方差贡献 → 旋转），并生成因子得分与洞察报告。

**实现位置**：`report_tools.py` 中 `_llm_factor_analysis`（约 1740–1876 行）。触发条件：`model_type in {"correlation", "all", "factor_only"}`。

**方法说明**（Prompt 中规定的四步，由 LLM 按步骤推理并输出）：  

1. **第一步：构建指标数据矩阵**  
   - 从年报提取最近 3–5 年核心财务指标（至少 3 年）。  
   - 指标类别：盈利能力（ROE、ROA、净息差/净利润率等）、风险（不良率/资产减值率、资产负债率、资本充足率等）、效率（成本收入比、周转率、营业费用率等）。  
   - 要求：数值型、处理缺失值、对指标做标准化（Z-score）。  

2. **第二步：执行因子分析**  
   - 流程：计算相关系数矩阵 → 提取特征值 → 按特征值>1 确定因子数 → 计算因子载荷矩阵、共同度、方差贡献率与累计贡献率 → 因子旋转（如 Varimax）。  
   - 输出：因子载荷矩阵（指标 × 因子）、每个因子的「核心解释变量」与经济含义命名（如盈利因子、风险因子、效率因子）；方差贡献表（因子、特征值、方差贡献率、累计贡献率），累计贡献率要求 ≥80%。  

3. **第三步：计算年度因子得分**  
   - 计算各年各因子得分（标准化），并构建综合得分：综合得分 = Σ(因子得分 × 方差贡献率权重)。  
   - 输出：年份 × 因子1得分、因子2得分、因子3得分、综合得分的表。  

4. **第四步：因子洞察报告**  
   - 内容：因子结构识别、企业经营驱动拆解、年度变化趋势、风险提示、投资判断（偏盈利/风险/效率驱动，结构性改善或周期性波动，进攻/防守/观望）。  

5. **输出格式**  
   - 必须输出一个 JSON，包含：  
     - `factor_analysis`：`factors`、`factor_loadings`（因子名 → 指标→载荷）、`variance_explained`、`interpretation`（第四步精炼总结）、`data_points`；  
     - `factor_data_sufficiency`：`is_sufficient`、`reason`、`sample_description`。  
   - 若样本不足无法完成，则 `factors` 为空、`interpretation` 中说明原因。代码中还会把 LLM 的完整回复（含数据表、载荷表、方差表、得分表、第四步全文）存入 `factor_analysis.full_report` 供前端展示。

### 2.6 聚类分析（K-Means，规模—风险—增长）

**作用**：对标的（如贷款类别/业务分部/产品线）按规模、风险、增长等维度做 K-Means 聚类，并为每类赋予业务语义与战略含义，输出可解释的「客群—标的」分组。

**实现位置**：`report_tools.py` 中 `generate_profit_forecast_and_valuation` 内，当 `model_type in {"clustering", "all"}` 且尚未有 `clustering_model` 时（约 2435–2482 行），通过一段长 prompt 由 LLM 执行步骤并输出 JSON。

**方法说明**（Prompt 中规定的八步，LLM 在内部推理后只输出步骤七的 JSON）：  

1. **步骤一：明确聚类目标**  
   - 说明聚类对象（如贷款类别/业务分部/产品线）、聚类目的（规模分层、风险分层、增长分层、战略取舍、结构优化、投资决策支持等）。  

2. **步骤二：原始数据整理**  
   - 从年报提取横向可比数据：规模类（余额/收入/资产或占比）、风险质量类（不良率/违约率等）、成长性（同比/环比/CAGR），整理成表。  

3. **步骤三：数据标准化**  
   - 对数值做 Min-Max 或 Z-score 标准化；若某指标完全相同则说明对聚类贡献有限。  

4. **步骤四：执行 K-Means 聚类**  
   - 说明采用的 k 值及聚类过程。  

5. **步骤五：业务语义命名**  
   - 为每个簇赋予业务含义标签（如增长型核心资产、稳健基石资产、收缩调整资产），不得仅用 Cluster 1/2/3，并说明命名逻辑。  

6. **步骤六：聚类结果汇总**  
   - 聚类与成员、规模/风险/增长特征、战略含义；哪类是增长引擎、稳定器、需压降或调整，是否存在资源错配。  

7. **步骤七：结构化 JSON 输出**  
   - 必须且仅输出一个 JSON，且将聚类结果放在 `clustering_model` 键下，结构包括：  
     - `method`（如 "k-means"）、`k`、`dimensions`（如 ["规模","风险","增长"]）；  
     - `clusters`：每项含 `name`、`members`、`characteristics`、`strategy_implication`；  
     - `core_insights`（3–5 条）、`risk_notes`（1–3 条）。  

8. **步骤八**  
   - 要求先完成步骤一至六的推理与数据整理，最后仅输出步骤七的 JSON，不输出中间文字。  

代码会对解析出的 `clustering_model` 做兼容处理：若存在 `clusters` 而无 `group_results`，则从 `clusters` 生成 `group_results`；若无 `conclusion`，则从 `core_insights`、`risk_notes` 组装 `conclusion`（current_position、upgrade_conditions、high_growth_conditions）；若无 `variable_table` 则按 `dimensions` 生成占位行。

### 2.7 综合投资策略洞察（仅 model_type=all）

**作用**：在已有关联性分析、因子分析、聚类分析及策略结论的基础上，生成一份整合性的 Markdown 投资策略报告，包含四部分：相关性洞察、因子洞察、聚类洞察、综合投资策略建议。

**实现位置**：`report_tools.py` 中 `generate_profit_forecast_and_valuation` 末尾（约 2484–2611 行）。触发条件：`model_type == "all"` 且 `result_dict` 中至少存在 `correlation_results`、`factor_analysis` 或 `clustering_model` 之一。

**方法说明**：  
- 将 `correlation_results`、`factor_analysis`、`clustering_model`、`strategy_conclusion`、`variable_table` 以 JSON 形式填入 prompt。  
- 要求 LLM 生成：  
  - **一、相关性分析洞察**：强/中等相关关系、业务含义、反直觉发现、风险信号，并引用相关系数。  
  - **二、因子分析洞察**：各因子经济含义、因子解释力、主要业务维度、业务优化建议，并引用载荷与方差。  
  - **三、聚类分析洞察**：各聚类特征、业务策略模式、投资组合定位、投资建议（短期/中期/长期、投资者类型）。  
  - **四、综合投资策略建议**：整合上述发现、核心亮点、关键风险、短期/中期/长期投资建议、目标投资者画像。  
- 输出格式为 Markdown，标题结构为「# {公司名}投资策略分析报告」及四个二级标题。  
- 结果写入 `result_dict["comprehensive_insight"]`；若生成失败仅打日志，不改变已有结构化结果。  

---

## 三、章节展示与 API 返回

**ReportAgent.generate_section("profit_forecast")**（`report_agent.py` 约 473–601 行）：  

1. 使用 `model_type or "all"` 调用 `generate_profit_forecast_and_valuation`。  
2. **摘要文本（content）**：  
   - 若存在 `comprehensive_insight`，则直接作为章节展示内容；  
   - 否则由 `strategy_conclusion`（short_term、long_term、risk_control、key_signals）、因子分析的 `full_report`（经过去除末尾 JSON、标题简化等清洗）、聚类分析的 conclusion/core_insights/risk_notes/clusters 等拼接为多段文本。  
3. 返回：`status`、`section_name`、`content`、`structured_response.profit_forecast_and_valuation`（完整结构化数据）、`visualization`、`tool_calls`。  

**API**：  
- `POST /agent/generate-section`，body 中 `section_name="profit_forecast"`，可选 `model_type`（all / correlation_only / factor_only / clustering）。  
- `POST /agent/query` 中用户以自然语言请求「投资策略」时，由 Agent 决定调用 `generate_profit_forecast_and_valuation` 并传入相应 `model_type`。

## 四、数据模型摘要（论文可引用）

- **ProfitForecastAndValuation**（`models/report_models.py`）：  
  - `indicator_extraction`、`variable_table`、`correlation_results`、`strategy_conclusion`、`data_sufficiency`、`clustering_model`、`notes`；并可在运行时扩展 `factor_analysis`、`factor_data_sufficiency`、`comprehensive_insight`。  
- **CorrelationResult**：target_metric、driver_metric、correlation、significance、interpretation、data_points。  
- **StrategyConclusion**：short_term、long_term、risk_control、key_signals。  
- **ClusteringModel**：method、k、variable_table、group_results、conclusion；与 LLM 输出的 clusters/core_insights/risk_notes 有兼容映射。

## 五、论文方法章节可采用的表述要点

1. **数据层**：基于 RAG 对年报进行三路检索（表格、管理层讨论与经营分析、近三年核心指标），形成统一语料。  
2. **指标层**：通过 LLM 多维度抽取（7 类维度）并规范为输入变量表，强调 8 项核心指标至少三年时间序列。  
3. **相关性**：在变量表基础上由 LLM 构建时间序列并计算两两 Pearson 相关系数，满足至少 3 个共同时间点；并生成高/低相关性结论与关键信号。  
4. **因子分析**：标准流程（相关矩阵→特征值→因子数→载荷→方差贡献→旋转），年度因子得分与综合得分，以及因子洞察报告。  
5. **聚类分析**：规模—风险—增长三维 K-Means，业务语义命名与战略含义解释，输出客群—标的适配分组与投资定位。  
6. **综合策略**：仅在「全量」模式下，对相关性、因子、聚类与策略结论进行整合，生成结构化 Markdown 投资策略报告。  

以上流程与实现位置一一对应，便于在论文中按「数据获取 → 指标构建 → 相关性分析 → 因子分析 → 聚类分析 → 综合策略」的顺序撰写方法小节并标注代码位置。
