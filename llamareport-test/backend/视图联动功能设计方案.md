# 视图联动功能设计方案

## 📋 功能概述

**视图联动**是指用户点击现有视图后，系统基于该视图生成新的相关视图和深度洞察的功能。这实现了从"单一视图"到"视图网络"的升级，让用户能够深入探索数据背后的关联和洞察。

---

## 🎯 核心目标

1. **增强交互性**：用户可以通过点击视图进行深度探索
2. **生成新洞察**：基于现有视图生成更高阶的综合洞察
3. **视图网络化**：建立视图之间的关联关系，形成探索路径
4. **智能推荐**：自动推荐相关的验证型、解释型、导航型视图

---

## 🏗️ 架构设计

### 1. 整体流程（增强版 - 带数据验证）

```
用户点击视图
    ↓
前端捕获视图信息
    ├─ 视图ID
    ├─ 视图类型
    ├─ 视图数据摘要
    ├─ 原始查询和回答
    └─ 点击位置/区域（可选）
    ↓
后端接收联动请求
    ├─ 提取视图摘要（ChartSummary）
    ├─ 关联原始查询和文本
    └─ 调用联动生成引擎
    ↓
联动生成引擎（LLM驱动）🤖
    ├─ 阶段一：对齐分析（Align）- LLM执行
    │   └─ LLM分析视图特征与文本对齐
    ├─ 阶段二：综合推理（Synthesize）- LLM执行
    │   └─ LLM生成洞察和视图推荐
    ├─ 阶段三：数据需求分析 - LLM执行
    │   └─ LLM分析每个推荐视图需要什么数据
    └─ 阶段四：数据检索与验证（Data Retrieval & Validation）
        ├─ 根据LLM分析的数据需求构建查询
        ├─ 从RAG检索相关数据
        ├─ 验证数据完整性和质量
        └─ 评估数据可用性
    ↓
阶段五：新视图生成（View Generation）- LLM驱动🤖
    ├─ LLM根据数据验证结果生成视图策略
    ├─ 数据充足 → LLM生成完整视图配置
    ├─ 数据质量低 → LLM生成带警告的视图配置
    └─ 数据不足 → LLM生成数据请求视图和替代方案
    ↓
返回结果
    ├─ 新视图列表（带数据质量标记）
    ├─ 综合洞察
    ├─ 视图关联关系
    └─ 数据验证报告（可选）
```

### 2. 联动生成引擎（LinkageGenerationEngine）- LLM驱动 🤖

**位置**：`agents/view_linkage.py`

**功能**：
- 使用LLM执行完整的联动分析流程

**实现思路**：
```python
class LinkageGenerationEngine:
    def __init__(self, llm=None):
        self.llm = llm or Settings.llm
    
    async def generate_linkage_analysis(
        self,
        chart_summary: ChartSummary,
        original_query: str,
        original_answer: str,
        related_text: Optional[str] = None
    ) -> Dict[str, Any]:
        """
        使用LLM生成完整的联动分析
        
        流程：
        1. 对齐分析：视图特征与文本对齐
        2. 综合推理：生成洞察和证据链
        3. 数据需求分析：分析需要什么数据
        4. 视图生成策略：确定如何生成新视图
        
        返回：
        {
            "alignment_result": {...},
            "synthesis_insight": {...},
            "data_requirements": [...],
            "view_generation_strategy": [...]
        }
        """
        # 构建完整的Prompt，让LLM一次性完成所有分析
        prompt = self._build_linkage_analysis_prompt(
            chart_summary, original_query, original_answer, related_text
        )
        
        # 调用LLM
        response = await self._call_llm(prompt)
        
        # 解析LLM响应
        return self._parse_llm_response(response)
    
    def _build_linkage_analysis_prompt(
        self,
        chart_summary: ChartSummary,
        original_query: str,
        original_answer: str,
        related_text: Optional[str]
    ) -> str:
        """
        构建联动分析的完整Prompt
        """
        return f"""
你是一个专业的财务分析专家，擅长分析图表与文本的关联，并生成深度洞察。

## 任务
分析以下视图和文本内容，生成联动分析结果。

## 输入信息

### 1. 源视图摘要
视图类型：{chart_summary.chart_type.value}
视图标题：{chart_summary.title}
时间范围：{chart_summary.time_range}
关键指标：{', '.join(chart_summary.key_metrics)}
数据模式：
- 趋势：{chart_summary.patterns.get('trend', '未知')}
- 拐点：{chart_summary.patterns.get('turning_points', [])}
- 异常：{chart_summary.patterns.get('anomalies', [])}

### 2. 原始查询
{original_query}

### 3. 原始回答
{original_answer}

### 4. 相关文本（可选）
{related_text if related_text else '无'}

## 分析任务

请完成以下四个阶段的分析：

### 阶段一：对齐分析（Align）
分析视图特征与文本内容的对齐关系：
1. 时间匹配：图表中的时间点（拐点、异常点）是否与文本中的事件时间匹配？
2. 逻辑对齐：文本中的断言是否能解释图表中的变化？
3. 证据评估：现有证据是否充分？缺少哪些证据？

### 阶段二：综合推理（Synthesize）
基于对齐结果，生成综合洞察：
1. 一句话结论（不超过50字）
2. 证据链（列出图表特征和文本断言的对应关系）
3. 置信度评估（高/中/低）及原因
4. 关键发现（3-5条）

### 阶段三：数据需求分析
分析需要生成哪些新视图来验证或解释洞察，每个视图需要什么数据：
1. 推荐视图列表（验证型/解释型/导航型）
2. 每个视图的数据需求：
   - 需要什么数据（指标、维度、时间范围）
   - 数据来源建议（从哪些文档/表格中检索）
   - 数据完整性要求（最少需要多少数据点）

### 阶段四：视图生成策略
根据数据可用性，确定视图生成策略：
1. 如果数据充足，如何生成完整视图？
2. 如果数据部分可用，如何生成带警告的视图？
3. 如果数据不足，如何生成数据请求视图或替代方案？

## 输出格式（JSON）

            }}
        ],

        "key_findings": ["发现1", "发现2", "发现3"]
    }},
    "data_requirements": [
        {{
            "view_type": "verify/explain/navigate",
            "view_description": "视图描述",
            "view_reason": "为什么需要这个视图",
            "required_data": {{
                "data_type": "breakdown/time_series/events/comparison",
                "main_metric": "主要指标",
                "dimensions": ["维度1", "维度2"],
                "time_range": {{"start": "2022", "end": "2024"}},
                "required_fields": ["字段1", "字段2"],
                "min_data_points": 3,
                "data_source_hints": ["从利润表检索", "从业务描述中提取"]
            }}
        }}
    ],
    "view_generation_strategy": [
        {{
            "view_index": 0,
            "strategy": {{
                "if_data_sufficient": {{
                    "chart_type": "grouped_bar",
                    "description": "生成分组柱状图，展示各渠道营收趋势",
                    "key_points": ["重点展示零售渠道增长", "标注2024Q2拐点"]
                }},
                "if_data_partial": {{
                    "chart_type": "line",
                    "description": "生成折线图，但添加数据质量警告",
                    "warning_message": "数据不完整，仅显示2023-2024年数据",
                    "key_points": ["标注数据缺失"]
                }},
                "if_data_insufficient": {{
                    "view_type": "data_request",
                    "description": "生成数据请求视图",
                    "missing_data_description": "缺少渠道拆分数据",
                    "suggested_queries": [
                        "查询：营业收入 按渠道拆分",
                        "查询：营业收入 业务结构"
                    ],
                    "alternative_views": [
                        "如果无法获取拆分数据，可以生成总体营收趋势对比图"
                    ]
                }}
            }}
        }}
    ]
}}

请仔细分析，确保输出格式正确。
"""
    
    async def _call_llm(self, prompt: str) -> str:
        """调用LLM"""
        from llama_index.core import Settings
        from llama_index.core.llms import ChatMessage
        
        messages = [
            ChatMessage(
                role="system",
                content="你是一个专业的财务分析专家，擅长分析图表与文本的关联，并生成深度洞察。请严格按照JSON格式输出。"
            ),
            ChatMessage(role="user", content=prompt)
        ]
        
        response = self.llm.chat(messages)
        return response.message.content
    
    def _parse_llm_response(self, response: str) -> Dict[str, Any]:
        """解析LLM响应"""
        import json
        import re
        
        # 尝试提取JSON部分
        json_match = re.search(r'\{.*\}', response, re.DOTALL)
        if json_match:
            try:
                return json.loads(json_match.group())
            except:
                pass
        
        # 如果提取失败，尝试直接解析
        try:
            return json.loads(response)
        except:
            # 如果都失败，返回错误
            logger.error(f"无法解析LLM响应: {response}")
            return {
                "error": "LLM响应解析失败",
                "raw_response": response
            }
```

### 5. 新视图生成器（NewViewGenerator）- LLM驱动 🤖

**位置**：`agents/view_linkage.py`

**功能**：
- 使用LLM根据数据验证结果生成新视图配置
- 支持三种类型：验证型、解释型、导航型
- **关键改进**：LLM智能决策如何生成视图

**实现思路**：
```python
class NewViewGenerator:
    def __init__(self, query_engine, rag_engine, data_retriever, llm=None):
        self.query_engine = query_engine
        self.rag_engine = rag_engine
        self.data_retriever = data_retriever
        self.llm = llm or Settings.llm
    
    async def generate_views(
        self,
        linkage_analysis: Dict[str, Any],  # LLM生成的联动分析结果
        chart_summary: ChartSummary,
        company_name: str,
        year: str
    ) -> List[VisualizationResponse]:
        """
        生成新视图（LLM驱动）
        
        流程：
        1. 获取LLM分析的数据需求和生成策略
        2. 检索并验证数据
        3. 根据数据验证结果，使用LLM生成视图配置
        """
        data_requirements = linkage_analysis.get("data_requirements", [])
        view_strategies = linkage_analysis.get("view_generation_strategy", [])
        
        new_views = []
        
        for i, (requirement, strategy) in enumerate(zip(data_requirements, view_strategies)):
            # 1. 检索并验证数据
            data_result = await self.data_retriever.retrieve_and_validate_data(
                requirement, chart_summary, company_name, year
            )
            
            # 2. 根据数据验证结果，选择生成策略
            if data_result["data_available"] and data_result["data_quality"] in ["high", "medium"]:
                # 数据充足，使用LLM生成完整视图
                view = await self._generate_view_with_llm(
                    requirement,
                    strategy.get("if_data_sufficient", {}),
                    data_result,
                    chart_summary
                )
            elif data_result["data_available"] and data_result["data_quality"] == "low":
                # 数据质量低，使用LLM生成带警告的视图
                view = await self._generate_view_with_llm(
                    requirement,
                    strategy.get("if_data_partial", {}),
                    data_result,
                    chart_summary
                )
            else:
                # 数据不足，使用LLM生成数据请求视图或替代方案
                view = await self._generate_view_with_llm(
                    requirement,
                    strategy.get("if_data_insufficient", {}),
                    data_result,
                    chart_summary
                )
            
            # 添加元数据
            view.metadata = {
                "data_quality": data_result["data_quality"],
                "data_sources": data_result["data_sources"],
                "validation_status": "passed" if data_result["data_available"] else "failed",
                "view_type": requirement["view_type"]
            }
            
            new_views.append(view)
        
        return new_views
    
    async def _generate_view_with_llm(
        self,
        requirement: Dict[str, Any],
        strategy: Dict[str, Any],
        data_result: Dict[str, Any],
        chart_summary: ChartSummary
    ) -> VisualizationResponse:
        """
        使用LLM生成视图配置
        
        LLM会根据：
        1. 视图需求（requirement）
        2. 生成策略（strategy）
        3. 实际数据（data_result）
        
        智能生成最适合的视图配置
        """
        prompt = self._build_view_generation_prompt(
            requirement, strategy, data_result, chart_summary
        )
        
        # 调用LLM生成视图配置
        response = await self._call_llm_for_view(prompt)
        
        # 解析并构建VisualizationResponse
        return self._parse_view_response(response, requirement, data_result)
    
    def _build_view_generation_prompt(
        self,
        requirement: Dict[str, Any],
        strategy: Dict[str, Any],
        data_result: Dict[str, Any],
        chart_summary: ChartSummary
    ) -> str:
        """
        构建视图生成的Prompt

    def _analyze_view_requirements(
        self,
        synthesis_insight: Dict[str, Any],
        chart_summary: ChartSummary
    ) -> List[Dict[str, Any]]:
        """
        分析视图需求
        
        根据洞察类型和源视图，确定需要什么数据
        """
        requirements = []
        
        # 从综合洞察中提取推荐视图
        recommended_views = synthesis_insight.get("recommended_views", [])
        
        for view_rec in recommended_views:
            view_type = view_rec["type"]  # verify/explain/navigate
            
            if view_type == "verify":
                # 验证型视图需要的数据
                requirement = {
                    "view_type": "verify",
                    "required_data": self._get_verification_data_requirements(
                        view_rec, chart_summary
                    ),
                    "description": view_rec.get("reason", "")
                }
            elif view_type == "explain":
                # 解释型视图需要的数据
                requirement = {
                    "view_type": "explain",
                    "required_data": self._get_explanation_data_requirements(
                        view_rec, chart_summary
                    ),
                    "description": view_rec.get("reason", "")
                }
            else:  # navigate
                # 导航型视图通常不需要额外数据
                requirement = {
                    "view_type": "navigate",
                    "required_data": {},  # 使用现有数据
                    "description": view_rec.get("reason", "")
                }
            
            requirements.append(requirement)
        
        return requirements
    
    def _get_verification_data_requirements(
        self,
        view_rec: Dict[str, Any],
        chart_summary: ChartSummary
    ) -> Dict[str, Any]:
        """
        获取验证型视图的数据需求
        """
        reason = view_rec.get("reason", "").lower()
        
        if "拆分" in reason or "业务线" in reason or "渠道" in reason:
            # 需要拆分数据
            return {
                "data_type": "breakdown",
                "main_metric": chart_summary.key_metrics[0] if chart_summary.key_metrics else "营业收入",
                "breakdown_dimension": self._extract_dimension_from_reason(reason),
                "time_range": chart_summary.time_range,
                "required_fields": ["dimension_name", "values", "time_period"]
            }
        elif "对比" in reason or "对照组" in reason:
            # 需要对比数据
            return {
                "data_type": "comparison",
                "metrics": chart_summary.key_metrics,
                "comparison_type": "historical/peer",
                "time_range": chart_summary.time_range,
                "required_fields": ["comparison_metric", "values", "time_period"]
            }
        elif "事件" in reason or "标注" in reason:
            # 需要事件数据
            return {
                "data_type": "events",
                "time_range": chart_summary.time_range,
                "required_fields": ["event_name", "event_time", "event_description"],
                "related_metrics": chart_summary.key_metrics
            }
        else:
            # 默认：需要相关指标的时间序列数据
            return {
                "data_type": "time_series",
                "metrics": chart_summary.key_metrics,
                "time_range": chart_summary.time_range,
                "required_fields": ["values", "time_period"]
            }
    
    def _get_explanation_data_requirements(
        self,
        view_rec: Dict[str, Any],
        chart_summary: ChartSummary
    ) -> Dict[str, Any]:
        """
        获取解释型视图的数据需求
        """
        reason = view_rec.get("reason", "").lower()
        
        if "路径" in reason or "因果" in reason:
            # 需要因果路径数据
            return {
                "data_type": "causal_path",
                "source_metric": chart_summary.key_metrics[0] if chart_summary.key_metrics else None,
                "required_fields": ["path_nodes", "path_links", "intermediate_metrics"]
            }
        elif "滞后" in reason or "响应" in reason:
            # 需要滞后响应数据
            return {
                "data_type": "lagged_response",
                "cause_metric": self._extract_cause_metric(reason),
                "effect_metric": chart_summary.key_metrics[0] if chart_summary.key_metrics else None,
                "time_range": chart_summary.time_range,
                "required_fields": ["cause_values", "effect_values", "time_period", "lag_period"]
            }
        else:
            # 默认：需要相关指标数据
            return {
                "data_type": "related_metrics",
                "metrics": chart_summary.key_metrics,
                "time_range": chart_summary.time_range,
                "required_fields": ["values", "time_period"]
            }
    
    async def _generate_full_view(

    async def _generate_view_with_warning(
```

```python
    """识别趋势：上升/下降/震荡"""
    if len(values) < 2:
        return "insufficient_data"
    
    # 计算斜率
    slopes = [values[i+1] - values[i] for i in range(len(values)-1)]
```

```python
def detect_turning_points(x: List[str], y: List[float]) -> List[Dict]:
    """识别拐点"""
    turning_points = []
    
    for i in range(1, len(y) - 1):
        # 检查是否是局部最大值或最小值
        if (y[i] > y[i-1] and y[i] > y[i+1]) or \
           (y[i] < y[i-1] and y[i] < y[i+1]):
            turning_points.append({
                "time": x[i],
                "value": y[i],
                "type": "peak" if y[i] > y[i-1] else "trough"
            })
    
    return turning_points
```

```python
        "missing_fields": List[str],
        "completeness_score": float,  # 0-1
        "data_point_count": int,
        "time_range_coverage": float  # 0-1
    }
    """
    missing = []
    for field in required_fields:
        if field not in retrieved_data or not retrieved_data[field]:
            missing.append(field)
    
    completeness = 1.0 - (len(missing) / len(required_fields))
    
    # 检查数据点数量
    values = retrieved_data.get("values", [])
    point_count = len(values) if values else 0
    
    # 检查时间范围覆盖
    time_range = retrieved_data.get("time_range")
    coverage = calculate_time_coverage(time_range, required_time_range)
    
    return {
        "is_complete": len(missing) == 0,
        "missing_fields": missing,
        "completeness_score": completeness,
        "data_point_count": point_count,
        "time_range_coverage": coverage
    }

def assess_data_quality(
    retrieved_data: Dict,
    validation_result: Dict
) -> str:
    """
    评估数据质量
    
    返回：high/medium/low
    """
    completeness = validation_result["completeness_score"]
    point_count = validation_result["data_point_count"]
    coverage = validation_result["time_range_coverage"]
    
    # 综合评分
    if completeness >= 0.9 and point_count >= 3 and coverage >= 0.8:
        return "high"
    elif completeness >= 0.7 and point_count >= 2:
        return "medium"
    else:
        return "low"
```

## ⚠️ 注意事项

### 1. 防幻觉机制

- **必须有证据链**：没有证据链不输出解释性结论
- **时间/逻辑对齐**：没有对齐只能输出"观察"
- **置信度控制**：无对照组时置信度不得为高
- **每条洞察必须推荐可验证视图**
- **⭐数据验证强制要求**：没有数据支撑的视图必须标记为"数据不足"，不能生成虚假视图

### 2. 数据质量保证

- **数据可用性检查**：生成视图前必须验证数据
- **数据质量标记**：每个视图必须标注数据质量（高/中/低）
- **缺失数据说明**：明确说明缺少哪些数据
- **建议查询提供**：数据不足时提供建议的查询方式
- **数据来源追踪**：记录数据来源，便于验证

### 3. 性能考虑

- **视图摘要缓存**：避免重复计算
- **数据检索优化**：使用HybridRetriever提高检索精度
- **数据验证缓存**：缓存数据验证结果（相同查询）
- **LLM调用优化**：合并对齐和综合推理（可选）
- **异步处理**：数据检索和视图生成使用异步，避免阻塞

### 4. 用户体验

- **加载状态**：显示"正在检索数据..." → "正在生成视图..."
- **数据质量提示**：在视图上显示数据质量标记（图标/标签）
- **数据不足提示**：数据不足时显示友好的提示和建议
- **错误处理**：联动失败时提供降级方案（返回数据请求视图）
- **交互反馈**：点击后立即反馈，异步加载结果
- **视图状态标识**：用不同颜色/图标标识视图状态（完整/警告/数据不足）

### 5. 数据检索策略优化

- **查询优化**：构建精确的查询，提高检索成功率
- **上下文过滤**：使用公司名、年份等过滤，提高相关性

- **数据提取优化**：使用LLM从文本中提取结构化数据
- **数据补全**：如果部分数据缺失，尝试从其他来源补全

```python
        "retrieved_data": extracted,
        "validation": {
            "completeness": completeness,
            "quality": quality,
            "missing_fields": completeness["missing_fields"]
        },
        "sources": result["sources"],
        "suggested_queries": generate_suggested_queries(
            requirement, completeness["missing_fields"]
        ) if not completeness["is_complete"] else []
    }

def generate_suggested_queries(
    requirement: Dict[str, Any],
    missing_fields: List[str]
) -> List[str]:
    """
    根据缺失字段生成建议查询
    """
    suggestions = []
    
    for field in missing_fields:
        if "时间" in field or "历史" in field:
            suggestions.append(f"查询历史数据：{requirement.get('main_metric', '相关指标')} 历史数据")
        elif "拆分" in field or "维度" in field:
            suggestions.append(f"查询拆分数据：{requirement.get('main_metric', '相关指标')} 按维度拆分")
        elif "对比" in field:
            suggestions.append(f"查询对比数据：{requirement.get('main_metric', '相关指标')} 对比分析")
    
    return suggestions
```

视图联动功能将显著提升系统的交互性和洞察深度。通过**视图摘要 → 对齐分析 → 综合推理 → 数据检索与验证 → 新视图生成**的完整流程，用户可以：

## 🤖 LLM驱动的核心优势

### 1. 联动分析引擎（LLM驱动）

**优势**：
- ✅ **上下文连贯性**：LLM可以同时考虑视图、文本、查询等所有信息，生成更一致的分析
- ✅ **灵活智能**：LLM可以根据具体情况灵活调整分析策略，不受硬编码规则限制
- ✅ **专业深度**：LLM可以生成更专业、更深入的洞察，接近人类专家的分析水平
- ✅ **一次调用**：一次LLM调用完成对齐、推理、需求分析、策略制定，提高效率

**对比传统方法**：
| 方面 | 规则驱动 | LLM驱动 |
|------|---------|---------|
| 灵活性 | ❌ 受规则限制 | ✅ 灵活适应 |
| 专业性 | ⚠️ 依赖规则质量 | ✅ 接近专家水平 |
| 上下文理解 | ⚠️ 难以整合 | ✅ 全面理解 |
| 维护成本 | ❌ 需要频繁更新规则 | ✅ 通过Prompt优化 |

### 2. 视图生成引擎（LLM驱动）

**优势**：
- ✅ **智能适配**：LLM根据实际数据情况，生成最合适的视图配置
- ✅ **边界处理**：LLM可以优雅处理各种边界情况（数据不足、部分可用等）
- ✅ **专业建议**：LLM可以提供专业的可视化建议（图表类型、布局、标注等）
- ✅ **用户友好**：生成的数据请求视图更清晰、更有帮助，提供替代方案

**对比传统方法**：
| 方面 | 模板驱动 | LLM驱动 |
|------|---------|---------|
| 适配性 | ❌ 模板固定 | ✅ 智能适配 |
| 边界处理 | ⚠️ 需要大量if-else | ✅ 自然处理 |
| 可视化质量 | ⚠️ 依赖模板设计 | ✅ 专业建议 |
| 用户体验 | ⚠️ 可能生硬 | ✅ 更友好 |

### 3. 实施建议

**LLM Prompt优化**：
1. **结构化输入**：清晰组织所有输入信息（视图摘要、查询、回答等）
2. **分阶段任务**：明确要求LLM完成各个阶段的分析
3. **输出格式**：要求严格的JSON格式，便于解析和验证
4. **示例引导**：在Prompt中提供示例，引导LLM生成正确格式
5. **错误处理**：设计降级方案，当LLM解析失败时使用备用逻辑

**性能优化**：
1. **Prompt缓存**：对于相同的输入，可以缓存LLM响应
2. **流式输出**：对于长响应，使用流式输出提高用户体验
3. **超时控制**：设置合理的超时时间，避免长时间等待
4. **重试机制**：LLM调用失败时，可以重试或使用降级方案

**质量控制**：
1. **输出验证**：验证LLM输出的JSON格式和必需字段
2. **数据验证**：即使LLM生成了视图配置，也要验证数据的有效性
3. **降级方案**：LLM失败时，使用规则或模板作为降级方案
4. **日志记录**：记录LLM的输入输出，便于调试和优化
