# `/agent/query` 和 `/query/ask` 接口对比说明

## 📊 核心区别概览

| 特性 | `/agent/query` | `/query/ask` |
|------|---------------|--------------|
| **架构** | Agent驱动（LLM Agent + 工具调用） | 直接RAG查询 |
| **智能程度** | ⭐⭐⭐⭐⭐ 高（可调用多个工具） | ⭐⭐⭐ 中（仅RAG检索） |
| **响应时间** | 较慢（可能需要多次LLM调用） | 较快（单次查询） |
| **可视化生成** | 条件性（Agent判断是否需要） | 可强制（`enable_visualization: true`） |
| **工具调用** | ✅ 支持（财务点评、业绩指引等） | ❌ 不支持 |
| **结构化数据** | ✅ 支持（structured_response） | ❌ 不支持 |
| **适用场景** | 复杂分析、章节生成 | 简单查询、强制可视化 |

---

## 🔍 详细对比

### 1. `/agent/query` - Agent智能查询接口

**路径**：`POST /agent/query`

**实现位置**：`backend/api/agent.py`

**核心特点**：
- ✅ **Agent驱动**：使用 `ReportAgent`，基于 LlamaIndex 的 FunctionAgent
- ✅ **工具调用能力**：可以调用多个专业工具
  - `annual_report_query`：基础查询工具
  - `generate_financial_review`：生成财务点评
  - `generate_business_guidance`：生成业绩指引
  - `generate_visualization`：生成可视化
  - `generate_dupont_analysis`：生成杜邦分析
  - 等等...
- ✅ **智能决策**：Agent 会根据问题自动选择最合适的工具
- ✅ **结构化响应**：可以返回结构化的数据（如财务点评的结构化数据）
- ⚠️ **可视化生成**：条件性生成，需要满足一定条件才会生成

**工作流程**：
```
用户问题
    ↓
ReportAgent.query()
    ↓
Agent 分析问题
    ↓
选择并调用工具（可能多个）
    ├─ annual_report_query（基础查询）
    ├─ generate_financial_review（如果需要）
    ├─ generate_visualization（如果需要）
    └─ ...
    ↓
整合工具结果
    ↓
返回综合响应
```

**返回格式**：
```json
{
    "status": "success",
    "question": "用户问题",
    "answer": "文本回答",
    "tool_calls": [
        {
            "tool_name": "annual_report_query",
            "tool_output": {...}
        }
    ],
    "structured_response": {...},  // 可选
    "visualization": {...}  // 可选，条件性生成
}
```

**优点**：
- 🎯 智能：能理解复杂问题并调用合适的工具
- 🔧 灵活：可以组合多个工具完成复杂任务
- 📊 结构化：可以返回结构化的分析结果

**缺点**：
- ⏱️ 较慢：可能需要多次工具调用，响应时间较长
- 🎲 不确定性：可视化生成是条件性的，不一定每次都有
- 💰 成本高：需要多次LLM调用

---

### 2. `/query/ask` - 直接RAG查询接口

**路径**：`POST /query/ask`

**实现位置**：`backend/api/query.py`

**核心特点**：
- ✅ **直接RAG查询**：直接调用 `RAGEngine.query()`
- ✅ **简单直接**：不经过Agent，直接检索和回答
- ✅ **强制可视化**：可以通过 `enable_visualization: true` 强制生成可视化
- ❌ **无工具调用**：不能调用专业工具
- ❌ **无结构化数据**：只返回文本回答

**工作流程**：
```
用户问题
    ↓
RAGEngine.query()
    ↓
RAG检索相关文档
    ↓
生成文本回答
    ↓
（可选）生成可视化
    ↓
返回响应
```

**返回格式**：
```json
{
    "question": "用户问题",
    "answer": "文本回答",
    "sources": [...],
    "context_filter": {...},
    "enhanced_query": "增强后的查询",
    "visualization": {...}  // 如果 enable_visualization: true
}
```

**请求参数**：
```json
{
    "question": "用户问题",
    "enable_visualization": true,  // 强制启用可视化
    "context_filter": {...}  // 可选
}
```

**优点**：
- ⚡ 快速：单次查询，响应速度快
- 🎯 可控：可以强制生成可视化
- 💰 成本低：只需要一次LLM调用（如果生成可视化）

**缺点**：
- 🧠 简单：不能处理复杂任务
- 🔧 无工具：不能调用专业工具
- 📊 无结构化：只返回文本，没有结构化数据

## 🎯 使用场景建议

### 使用 `/agent/query` 的场景：

1. **复杂分析需求**
   - "请帮我分析一下平安银行2024年的财务情况"
   - "生成财务点评"
   - "生成业绩指引"

2. **需要结构化数据**
   - 需要财务点评的结构化数据
   - 需要业绩指引的结构化数据

3. **多步骤任务**
   - 需要先查询数据，再进行分析，再生成报告

### 使用 `/query/ask` 的场景：

1. **简单查询**
   - "平安银行2024年的营业收入是多少？"
   - "ROE是多少？"

2. **强制需要可视化**
   - 无论问题如何，都需要生成可视化视图
   - 作为 `/agent/query` 的降级方案

3. **快速响应需求**
   - 需要快速得到答案，不需要复杂分析

## 🔄 当前前端实现策略

**当前策略**（`frontend/main.js`）：
```javascript
// 1. 先调用 /agent/query（智能查询）
const result = await fetch('/agent/query', {...})

// 2. 如果 Agent 没有生成可视化，降级到 /query/ask
if (!hasVisualization && result.answer.length > 50) {
    const vizResponse = await fetch('/query/ask', {
        enable_visualization: true  // 强制生成可视化
    })
}
```

**优势**：
- ✅ 优先使用智能Agent（如果Agent生成了可视化，就用Agent的）
- ✅ 确保总是有可视化（如果Agent没有，强制生成）
- ✅ 兼顾智能性和可靠性

## 📝 总结

| 维度 | `/agent/query` | `/query/ask` |
|------|---------------|--------------|
| **定位** | 智能分析助手 | 快速查询工具 |
| **核心能力** | 工具调用、智能决策 | RAG检索、强制可视化 |
| **适用问题** | 复杂、需要分析 | 简单、需要快速响应 |
| **可视化** | 条件性（智能判断） | 可强制（参数控制） |
| **响应时间** | 较慢（可能多次调用） | 较快（单次调用） |
| **成本** | 较高（多次LLM调用） | 较低（单次LLM调用） |

**最佳实践**：
- 复杂问题 → 使用 `/agent/query`
- 简单问题 + 需要可视化 → 使用 `/query/ask`
- 当前策略 → 先用 `/agent/query`，如果没有可视化，降级到 `/query/ask`
