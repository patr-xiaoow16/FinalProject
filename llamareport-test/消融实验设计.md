## 📌 实验背景

### 系统功能说明

LlamaReport 的**视图联动功能**支持两种交互形式：

#### 交互形式1：卡片选择（Card Selection）
用户点击选中一张或多张可视化卡片，可选填"探索问题"，点击生成按钮，系统基于选中卡片的内容触发联动分析，生成新的可视化视图与洞察文本。

#### 交互形式2：数据点钻取（Data Point Drill-down）
用户直接点击某张图表中的特定数据点（如折线上某年的数据点、柱状图中某根柱子），系统识别该数据点的上下文，自动触发联动分析。

#### 联动视图生成流程（LLM 驱动，共 6 步）

```
【步骤1】提取交互上下文
  提取源视图的图表类型、标题、时间范围、关键指标、数据模式（趋势/拐点/异常）

【步骤2】识别联动意图
  LLM 判断用户意图（下钻明细、对比分析、解释原因、关联验证、时序演变等）

【步骤3】确定联动关系类型
  从7种关系类型中选择最匹配的一种：
    下钻关系（Drill-Down）、平行对比关系（Comparison）、因果解释关系（Explanation）
    上卷关系（Roll-Up）、关联关系（Correlation）、时序演变关系（Evolution）、验证关系（Validation）

【步骤3.5】检索领域知识（indicators.md）⭐核心步骤
  根据关键指标从 indicators.md 中检索对应的领域知识，包括：
    - 指标组成项（如 ROA = 净息差 + 非息贡献 - 成本 - 信贷成本 - 有效税率）
    - 适用场景描述
    - 建议图表类型（如 ROA 贡献瀑布图、因子贡献条形图）
  若 indicators.md 给出了组成项，required_data.dimensions 和 required_fields
  必须完整列出全部组成项，并优先采用建议图表类型

【步骤4】生成联动查询（参考 indicators.md 结果）
  确定需要检索的数据字段、维度、时间范围，
  并参考 视图选择.md 确定候选图表类型

【步骤5】检索相关数据
  系统调用 RAG 引擎，从 PDF/Excel 文档中检索与联动查询匹配的原始数据

【步骤6】生成新视图和洞察
  LLM 结合 indicators.md 的建议图表与 视图选择.md 的选型规则，
  最终选定图表类型，生成 Plotly 可视化配置 + 洞察文本
```

> **关键说明**：联动视图的图表类型**不是固定分类**，而是 LLM 依据 indicators.md（领域知识）和 视图选择.md（图表选型规范）动态选择，可以是柱状图、折线图、瀑布图、双轴图等任意合适的图表。

## 🎯 研究问题 RQ1

### 问题定义

**RQ1：视图联动功能的整体有效性**

| 子问题 | 核心度量 |
|--------|---------|
| 视图联动功能是否显著提升了用户的**分析效率**？ | 任务完成时间（TCT）、分析效率提升率（AEI） |
| 视图联动功能是否显著提升了**洞察质量**？ | 洞察质量评分（IQS）、证据链完整性（ECC） |

### 假设

```
H₀（零假设）: 有/无视图联动功能的分析效率和洞察质量无显著差异
H₁（备择假设）: 有视图联动功能的分析效率和洞察质量显著优于无联动
显著性水平: α = 0.05（Bonferroni 校正后 α' = 0.0125）
```

### 研究背景

视图联动通过"卡片选择"和"数据点钻取"两种方式触发，经过 indicators.md 领域知识检索 + 视图选择.md 图表选型两阶段 LLM 推理，生成与源视图语义相关的新可视化视图。**验证此功能整体有效性，是后续组件级消融实验（RQ2 起）的必要前提。**

## 🏗️ 实验组设置

本次 RQ1 实验设置 **2 个实验组**：

### 组1：基线组（Baseline — 完整系统）

```
代码标识: baseline
环境变量: ENABLE_VIEW_LINKAGE=true

启用内容:
  ✓ 卡片选择交互（含探索问题输入）
  ✓ 数据点钻取交互
  ✓ 完整 6 步联动生成流程
  ✓ indicators.md 领域知识检索（步骤3.5）
  ✓ 视图选择.md 图表选型参考
  ✓ RAG 文档数据检索（步骤5）
  ✓ LLM 视图生成 + 洞察文本输出

目的: 代表系统完整功能状态，作为参照基准
```

### 组2：对照组（NoLinkage — 完全移除视图联动）

```
代码标识: no_linkage
环境变量: ENABLE_VIEW_LINKAGE=false

禁用内容:
  ✗ 卡片选择联动按钮（UI 隐藏，无法触发）
  ✗ 数据点钻取（点击无响应）
  ✗ 整个 6 步联动生成流程
  ✗ 不生成任何联动视图和洞察文本

用户能力:
  - 只能查看系统已生成的独立视图
  - 无法通过交互获取新的关联视图
  - 需自行根据多个独立视图推断分析结论

目的: 模拟"无联动功能"基准状态
预期: 分析效率和洞察质量显著低于 Baseline 组
```

## 📝 实验任务设计

设计 **5 个分析任务**，每个任务均具备强区分性：**单模块初始报告存在明确的信息缺口**，必须通过视图联动才能填补。两组受试者完成完全相同的任务集。

> **两组操作差异说明**
> - **Baseline 组**：系统生成初始模块视图后，受试者可通过「卡片选择」或「数据点钻取」触发联动，LLM 自动检索 indicators.md → RAG 检索文档数据 → 生成联动视图，再得出结论
> - **NoLinkage 组**：受试者只能查看初始模块输出（文字 + 表格 + 图表），无法触发任何联动，需自行从现有信息中整合结论

> **任务区分性核心逻辑**
> 每个任务设计均满足：初始模块报告存在明确信息缺口 → 缺口恰好对应 indicators.md 中的某一条目 → Baseline 触发联动后 LLM 能自动填补该缺口 → NoLinkage 组在系统内无法自动获得等效信息。

### T1：利息净收入下降的量价归因

**起始模块**：财务点评

**分析问题**：财务点评显示利息净收入同比明显下降，但下降的根本原因是贷款规模收缩（量）还是净息差压缩（价）？息差下行是近年加速还是已趋于平稳？

**初始报告的信息缺口**：

财务点评系统输出为 5 张年度报表（资产结构表、负债结构表、营业收入结构表、营业支出结构表、现金流量表）。营业收入结构表仅呈现利息净收入的年度同比数字，**没有量价拆分（贷款规模 vs NIM）**，也**没有季度维度的息差走势图**。受试者看到"利息净收入下降 X%"，但无法判断驱动因素。

```
Baseline 操作路径:
  ① 点击营业收入结构表中「利息净收入」数据点
     → 触发数据点钻取（ViewLinkageRequest）
  ② view_linkage.py 步骤3.5 检索 indicators.md
     → 命中「季度息差趋势」条目：
       组成项 = 净息差（NIM）/ 贷款收益率（资产端核心价格）/ 存款付息率（负债端核心成本）
       建议图表 = 季度 NIM 折线图；资产 vs 负债双轴图；季度变动柱状图
     → 关键判断逻辑：贷款收益率降幅 > 存款成本降幅 → 息差压缩；连续季度下行 → 盈利未见底
  ③ LLM 生成联动视图（LLM 判断为 Drill-Down 关系）：
     → 历年净利差 + 贷款规模双轴图（区分量的贡献 vs 价的贡献）
     → 季度 NIM 折线图（显示息差是否加速下行还是趋稳）
  ④ 受试者可直接判断：利息净收入下降主因，以及息差走势是否触底

NoLinkage 限制:
  只能读取年度营收结构表数字，无法区分量价贡献，
  无季度 NIM 趋势，只能给出笼统的"息差压缩"结论，无法判断是否触底
```

### T2：业务亮点定性结论的营收结构数据验证

**起始模块**：业务亮点

**分析问题**：业务亮点报告称"手续费及佣金收入是新的增长引擎，中间业务占比持续提升"。财务数据是否真正支持这一定性判断？手续费占营收的比例三年来有多大实质性变化？

**初始报告的信息缺口**：

业务亮点系统输出为各业务板块的文字亮点描述（`BusinessHighlight.highlights`）+ 关键指标汇总（单期数值）。全部是**定性或单期定量**，**没有多年营收结构演变的可视化**。财务点评虽有营业收入结构表，但也是静态表格，**两个模块均无法提供手续费占比三年演变的堆叠图**。

```
Baseline 操作路径:
  ① 选择「业务亮点」卡片，输入探索问题："手续费收入占比是否实质性提升？"
     → 触发卡片选择（MultiCardLinkageRequest）
  ② view_linkage.py 步骤3.5 检索 indicators.md
     → 命中「营收结构（营业结构）」条目：
       组成项 = [利息净收入, 手续费及佣金净收入, 其他非利息收入]
       建议图表 = 堆叠柱状图 / 堆叠面积图
  ③ LLM 生成联动视图（LLM 判断为 Validation 关系）：
     → 三年营收结构堆叠柱状图（各组成项绝对值 + 占比标注）
     → 手续费净收入占总收入比例折线图（显示趋势变化）
  ④ 受试者可用量化图表核实：定性"新增长点"结论是否有数据支撑，占比提升是否显著

NoLinkage 限制:
  只能阅读业务亮点的文字描述，无多年结构演变可视化，
  若要核实需手动从财务点评表格中抄取数字计算占比，容易遗漏且缺乏直观性
```

### T3：业绩指引风险提示的历史量化核验

**起始模块**：业绩指引

**分析问题**：业绩指引风险提示中提到"不良率存在上升压力，拨备计提将侵蚀利润"。历史上不良率、拨备覆盖率、信贷成本三者的联动关系如何？当前拨备缓冲是否充足以应对风险？

**初始报告的信息缺口**：

业绩指引系统输出为**纯文本字段**：`expected_performance`（预期描述）、`key_metrics`（指标锚点列表）、`business_specific_guidance`（各业务指引）、`risk_warnings`（风险提示列表）。**没有任何历史数据图表**。受试者只能读到"不良率存在上升压力"的文字判断，但无法从业绩指引模块内获取历史资产质量指标的量化趋势来评估风险的严重程度。

```
Baseline 操作路径:
  ① 选择「风险提示」卡片，输入探索问题："资产质量风险的历史演变如何？"
     → 触发卡片选择（MultiCardLinkageRequest）
  ② view_linkage.py 步骤3.5 检索 indicators.md
     → 命中「资产质量（资产质量与拨备）」条目：
       组成项 = [拨备覆盖率, 不良率, 信贷成本]
       建议图表 = 柱状图 + 折线图双轴组合图
       适用场景：识别银行盈利可持续性；判断是否存在"利润平滑"行为
  ③ LLM 生成联动视图（LLM 判断为 Explanation 关系）：
     → 不良率 + 信贷成本历年折线图（左轴）+ 拨备覆盖率历年柱状图（右轴）
  ④ 受试者可直接判断：风险是突然恶化还是长期积累；当前拨备缓冲是否充足

NoLinkage 限制:
  只能读取风险提示文字，业绩指引模块内无任何历史数据，
  需手动跳转至财务点评资产结构表逐行寻找，无趋势可视化，难以判断风险严重程度
```

### T4：综合投资策略结论的历史 ROE 一致性验证

**起始模块**：投资策略（综合投资策略分析 + 估值锚点）

**分析问题**：投资策略的短期结论认为当前标的"具有估值修复空间，PB 处于历史低位"。但 ROE 连续下行通常伴随 PB 中枢系统性下移。当前 PB 究竟是真的历史低估，还是仅反映了市场对 ROE 持续下行的合理定价？

**初始报告的信息缺口**：

投资策略系统输出：`indicator_extraction`（指标抽取，含当期 PB / ROE 单期数值）、`variable_table`（输入变量表，含估值类 / 盈利类分项）、`strategy_conclusion`（短期 / 长期 / 风险管控结论文字）。所有输出均为**当期单点数值或文字结论**，**没有历史 PB 走势图，没有 PB 与 ROE 的多年关系图**，受试者无法核实"处于历史低位"这一判断是否属实。

```
Baseline 操作路径:
  ① 选择「综合投资策略核心结论」卡片，输入探索问题："PB 是否真的处于历史低位？"
     → 触发卡片选择（MultiCardLinkageRequest）
  ② view_linkage.py 步骤3.5 检索 indicators.md
     → variable_table 中含 ROE 指标 → 命中「ROE（净资产收益率）」条目：
       关键逻辑 = ROA 下降 → 经营能力恶化 → PB 中枢随 ROE 系统性下移
       建议图表 = ROE 瀑布图；柱状对比图（ROA vs 杠杆）
  ③ LLM 生成联动视图（LLM 判断为 Validation 关系）：
     → 历年 PB 走势折线图，叠加策略结论中给出的估值目标区间作为参考线
     → 历年 ROE vs PB 双轴图（验证 PB 中枢是否随 ROE 下移）
  ④ 受试者可直接判断：当前 PB 是否低于历史均值，以及 PB 低估是否由 ROE 下行解释

NoLinkage 限制:
  只能阅读策略结论文字和 variable_table 中的当期 PB/ROE 单点数值，
  无法看到历史 PB 走势或 PB-ROE 关系图，无法验证"历史低位"判断的真实性
```

### T5：杜邦 ROA 三因素的五因素深层分解

**起始模块**：杜邦分析

**分析问题**：杜邦分析将 ROA 拆解为净利润率 × 资产周转率（三因素），但对银行而言，ROA 下降究竟主要来自哪个具体因子：净息差收窄、非息收入萎缩、成本效率恶化还是信贷成本提高？各因子对 ROA 的正负贡献各是多少？

**初始报告的信息缺口**：

系统杜邦模型数据结构（`DupontLevel1`/`Level2`/`Level3`）**仅输出三因素**：ROE = ROA × 权益乘数，ROA = 净利润率 × 资产周转率，不含任何银行专项的因子分解。indicators.md 中的 **ROA 五因素拆解**（净息差 + 非息贡献 − 成本 − 信贷成本 − 有效税率）属于领域专业知识，**不在杜邦报告的默认输出范围内**，只有通过视图联动触发 indicators.md 检索才能获得。

```
Baseline 操作路径:
  ① 点击杜邦分解树中「ROA」数值 → 触发数据点钻取（ViewLinkageRequest）
  ② view_linkage.py 步骤3.5 检索 indicators.md
     → 命中「ROA（总资产收益率）」条目：
       五因素组成项 = 净息差 + 非息贡献 - 成本收入比 - 信贷成本 - 有效税率
       建议图表 = ROA 贡献瀑布图；因子贡献条形图；正负贡献分解图
       关键判断逻辑：NIM 下降 → 利率周期压缩；信贷成本下降 → 风险缓释；成本改善 → 内部效率
  ③ LLM 生成联动视图（LLM 判断为 Drill-Down 关系）：
     → ROA 五因素贡献瀑布图（各因子正负贡献量化，最终累计到当期 ROA）
     → 各因子历年变动趋势对比图（识别主要拖累项的变化节点与拐点）
  ④ 受试者可精确定位：ROA 下降的首要因子及其历年趋势，判断盈利压力是否触底

NoLinkage 限制:
  只能看到杜邦三因素聚合数值（净利润率 × 资产周转率），
```

## 📐 评估指标设计

RQ1 聚焦**分析效率**和**洞察质量**两个维度，共 5 项指标。

### 5.1 分析效率指标

#### 指标A：任务完成时间（Task Completion Time, TCT）

```
定义: 用户完成单个分析任务（从开始查看视图到提交分析结论）的总耗时（秒）

测量方式:
  - 前端记录用户进入任务页面的时间戳（t_start）
  - 前端记录用户点击"提交结论"的时间戳（t_end）
  - TCT = t_end - t_start

注意:
  - 两组均使用完全相同的计时逻辑
  - 排除系统响应等待时间（系统 API 调用时间不计入用户分析时间）

参考阈值:
  优秀 ≤ 5 分钟，良好 ≤ 10 分钟，及格 ≤ 15 分钟，不及格 > 15 分钟
```

#### 指标B：分析效率提升率（Analysis Efficiency Improvement, AEI）

```
定义: 有联动功能相对无联动功能的分析时间缩短比例

计算公式:
  AEI = (TCT_no_linkage - TCT_baseline) / TCT_no_linkage × 100%

评估方式:
  - 基于两组的平均 TCT 计算
  - 按任务类型分组计算（趋势分析 / 对比分析 / 异常识别各组 AEI）

参考阈值:
  优秀 ≥ 50%，良好 ≥ 30%，及格 ≥ 15%，不及格 < 15%
```

### 5.2 洞察质量指标

#### 指标C：洞察质量评分（Insight Quality Score, IQS）

```
定义: 用户通过分析得出的洞察结论的质量（深度、可操作性、新颖性）

评分维度（各1-5分，取平均）:
  深度    - 是否分析了根本原因（而非停留在现象描述）
  可操作性 - 结论是否可指导决策
  新颖性  - 是否提供了超出初始视图的新视角

评估方法:
  1. Baseline 组：评估联动视图 + 用户结论文本
  2. NoLinkage 组：评估用户仅凭独立视图得出的结论文本
  3. 由 3-5 名财务专业评估专家盲评（不知分组）
  4. 取专家评分均值

参考阈值:
  优秀 ≥ 4.5，良好 ≥ 4.0，及格 ≥ 3.5，不及格 < 3.5
```

#### 指标D：证据链完整性（Evidence Chain Completeness, ECC）

```
定义: 分析结论是否有完整可追溯的数据支撑

评分维度（各1-5分，取平均）:
  证据来源    - 结论是否标注或可追溯到具体数据
  证据充分性  - 支撑结论的数据是否充分
  逻辑连贯性  - 从数据到结论的推理是否连贯

评估方法:
  - Baseline 组：检查联动视图的 indicators.md 组成项是否被完整引用
  - NoLinkage 组：检查用户结论的数据依据是否明确
  - 专家盲评，1-5 分

参考阈值:
  优秀 ≥ 4.5，良好 ≥ 4.0，及格 ≥ 3.5，不及格 < 3.5
```

#### 指标E：用户满意度（User Satisfaction, US）

```
定义: 用户对本次分析体验的整体满意度

问卷（每任务结束后即时填写，5点李克特量表）:
  Q1: 本次分析体验是否提升了您的分析效率？    □1 □2 □3 □4 □5
  Q2: 您在分析过程中获得的洞察是否有价值？    □1 □2 □3 □4 □5
  Q3: 您是否愿意继续使用当前方式进行分析？    □1 □2 □3 □4 □5
  Q4: 您是否会向同事推荐当前分析方式？（NPS） □0-10

US = (Q1 + Q2 + Q3) / 3

参考阈值:
  优秀 ≥ 4.5，良好 ≥ 4.0，及格 ≥ 3.5，不及格 < 3.5
```

### 5.3 指标汇总表

| 指标 | 简称 | 度量维度 | 采集方式 | 适用组 |
|------|------|---------|---------|--------|
| 任务完成时间 | TCT | 分析效率 | 前端自动记录（秒） | 两组 |
| 分析效率提升率 | AEI | 分析效率 | 公式推导 | 跨组计算 |
| 洞察质量评分 | IQS | 洞察质量 | 专家盲评（1-5） | 两组 |
| 证据链完整性 | ECC | 洞察质量 | 专家盲评（1-5） | 两组 |
| 用户满意度 | US | 综合体验 | 用户问卷（1-5） | 两组 |

### 7.2 统计显著性检验

```python
from scipy import stats

def test_rq1(metric_b, metric_nl, metric_name, alternative='less'):
    """
    alternative='less'  → 检验 Baseline < NoLinkage（TCT 越小越好）
    alternative='greater' → 检验 Baseline > NoLinkage（IQS/ECC/US 越大越好）
    """
    # 正态性检验
    _, p_norm = stats.shapiro(metric_b)
    if p_norm > 0.05:
        stat, p = stats.ttest_ind(metric_b, metric_nl, alternative=alternative)
        method = "独立样本 t 检验"
    else:
        stat, p = stats.mannwhitneyu(metric_b, metric_nl, alternative=alternative)
        method = "Mann-Whitney U 检验"

    # Cohen's d 效应量
    pooled_std = np.sqrt((np.std(metric_b, ddof=1)**2 + np.std(metric_nl, ddof=1)**2) / 2)
    d = abs(np.mean(metric_b) - np.mean(metric_nl)) / pooled_std

    sig = "✅ 显著" if p < 0.0125 else "❌ 不显著"  # Bonferroni α' = 0.05/4
    print(f"{metric_name}: {method}, p={p:.4f} {sig}, Cohen's d={d:.2f}")
    return p, d

# 执行四项检验
p_tct, d_tct = test_rq1(baseline_tct, no_linkage_tct, "TCT",  alternative='less')
p_iqs, d_iqs = test_rq1(baseline_iqs, no_linkage_iqs, "IQS",  alternative='greater')
p_ecc, d_ecc = test_rq1(baseline_ecc, no_linkage_ecc, "ECC",  alternative='greater')
p_us,  d_us  = test_rq1(baseline_us,  no_linkage_us,  "US",   alternative='greater')
```

**效应量解释**

```
d < 0.2  → 小效应（实践意义有限）
0.2-0.5  → 中效应
0.5-0.8  → 大效应
d ≥ 0.8  → 非常大效应（高实践价值）
```

## 📌 实验注意事项

### 9.1 避免偏差

```
1. 随机化
   - 任务顺序在受试者之间随机（避免学习效应）
   - 同一任务数据集在两组间完全一致

2. 盲法
   - NoLinkage 组受试者不知道有联动功能存在（不同培训内容）
   - 专家评分时不知道结论来自哪组（匿名化处理）

3. 控制混淆变量
   - 两组使用同一批年报数据
   - 两组环境 LLM 版本、向量库、提示词完全一致
   - 实验在同一时段进行，避免 API 响应差异
```

### 9.2 样本量要求

```
最小样本量（独立样本 t 检验）:
  α = 0.05，统计功效 = 0.80，效应量 d = 0.5（保守估计）
  → 每组最小 n ≥ 34 个数据点

当前设计:
  10 任务 × 5 名受试者 = 50 个数据点 / 组  ✅ 满足要求

若受试者 < 5 人，需增加任务数量（如 34 个任务 × 2 名受试者）
```

### 9.3 多重比较校正

```
本次 RQ1 共进行 4 项假设检验（TCT、IQS、ECC、US）
采用 Bonferroni 校正: α' = 0.05 / 4 = 0.0125
仅当 p < 0.0125 时才认为存在统计显著差异
```

### 9.4 异常值处理

```
TCT 异常值（如用户中途离开导致超时）:
  - 使用 IQR 法识别: 超出 Q3 + 1.5 × IQR 的记录
  - 查明原因后决定保留或剔除，并在报告中说明

专家评分一致性:
  - 计算评分者间一致性（ICC）
  - ICC ≥ 0.70 为良好，< 0.70 需重新培训后补评
```
